# Exercise 4: Git Merge Conflict Resolution

## Objectives & Detailed Explanation

1. **Understand Git Merge Conflicts & Why They Occur**:
   - A **Merge Conflict** occurs in Git when changes are made to the same line of the same file on two different branches, or when one branch modifies a file while another branch deletes it.
   - Git cannot automatically determine which set of changes is correct without developer intervention.

2. **Understand Git Conflict Markers (`<<<<<<<`, `=======`, `>>>>>>>`)**:
   - When a conflict occurs during `git merge`, Git places special markup flags directly inside the conflicting file:
     - `<<<<<<< HEAD` : Indicates changes present in the currently active branch (`master`/`main`).
     - `=======` : The divider separating the conflicting changes.
     - `>>>>>>> <branch_name>` : Indicates changes coming from the merging branch (`GitWork`).

3. **Master Conflict Resolution & 3-Way Merge Workflow**:
   - Learn how to inspect conflicting files, decide which changes to keep or integrate, manually remove conflict markers, stage the resolved file (`git add`), and complete the merge commit (`git commit`).
   - Configure `.gitignore` rules to ignore merge backup/temporary files (such as `*.orig` or `*.bak` files generated by merge tools like P4Merge).

## Exercise Steps & Commands

### Task Requirement
Create a conflict scenario by adding `hello.xml` with different contents in both `master` and feature branch `GitWork`. Attempt to merge `GitWork` into `master`, observe conflict markup, resolve the conflict, complete the merge commit, update `.gitignore` with backup file extensions (`*.orig`, `*.bak`), list branches, delete the merged branch, and observe the commit log graph.

---

### Step-by-Step Instructions & Commands

#### 1. Verify `master` is in clean state
```bash
git status
```
*Actual Execution Output:*
```text
On branch master
nothing to commit, working tree clean
```

#### 2. Create branch `GitWork` and add `hello.xml`
```bash
git checkout -b GitWork
echo "<note><to>User A</to><content>Branch Modification</content></note>" > hello.xml
```
*Actual Execution Output:*
```text
Switched to a new branch 'GitWork'
```

#### 3. Update content of `hello.xml` and observe status
```bash
git status
```
*Actual Execution Output:*
```text
On branch GitWork
Untracked files:
	hello.xml
```

#### 4. Commit changes to reflect in branch
```bash
git add hello.xml
git commit -m "Add hello.xml in GitWork branch"
```
*Actual Execution Output:*
```text
[GitWork 569703a] Add hello.xml in GitWork branch
 1 file changed, 1 insertion(+)
 create mode 100644 hello.xml
```

#### 5. Switch to `master`
```bash
git checkout master
```
*Actual Execution Output:*
```text
Switched to branch 'master'
```

#### 6. Add `hello.xml` to `master` with different content
```bash
echo "<note><to>User B</to><content>Master Modification</content></note>" > hello.xml
```

#### 7. Commit changes to `master`
```bash
git add hello.xml
git commit -m "Add conflicting hello.xml in master branch"
```
*Actual Execution Output:*
```text
[master e1ee2c9] Add conflicting hello.xml in master branch
 1 file changed, 1 insertion(+)
 create mode 100644 hello.xml
```

#### 8. Observe log graph across all branches
```bash
git log --oneline --graph --decorate --all
```
*Actual Execution Output:*
```text
* e1ee2c9 (HEAD -> master) Add conflicting hello.xml in master branch
| * 569703a (GitWork) Add hello.xml in GitWork branch
|/  
* f17047f Initial commit on master
```

#### 9. Check differences between `master` and `GitWork`
```bash
git diff master..GitWork
```

#### 10. Use visual diff tool / P4Merge to list differences
```bash
git difftool master GitWork
```

#### 11. Merge `GitWork` branch into `master` (Triggers Conflict)
```bash
git merge GitWork
```
*Actual Execution Output:*
```text
Auto-merging hello.xml
CONFLICT (add/add): Merge conflict in hello.xml
Automatic merge failed; fix conflicts and then commit the result.
```

#### 12. Observe Git markup & conflict status
```bash
git status
cat hello.xml
```
*Sample Conflict Markup in `hello.xml`:*
```xml
<<<<<<< HEAD
<note><to>User B</to><content>Master Modification</content></note>
=======
<note><to>User A</to><content>Branch Modification</content></note>
>>>>>>> GitWork
```

#### 13. Resolve conflict using 3-way merge tool or manual editing
Edit `hello.xml` to combine and resolve conflicting changes:
```xml
<note><to>User A and User B</to><content>Resolved Combined Modification</content></note>
```

#### 14. Stage and commit resolved conflict to `master`
```bash
git add hello.xml
git commit -m "Merge branch GitWork and resolve merge conflict in hello.xml"
```
*Actual Execution Output:*
```text
[master dc1260c] Merge branch GitWork and resolve merge conflict in hello.xml
```

#### 15. Add backup file extensions (`*.orig`, `*.bak`) to `.gitignore`
```bash
echo "*.orig" >> .gitignore
echo "*.bak" >> .gitignore
```

#### 16. Commit `.gitignore`
```bash
git add .gitignore
git commit -m "Add backup files *.orig and *.bak to .gitignore"
```
*Actual Execution Output:*
```text
[master d67c718] Add backup files *.orig and *.bak to .gitignore
 1 file changed, 2 insertions(+)
 create mode 100644 .gitignore
```

#### 17. List all available branches
```bash
git branch -a
```
*Actual Execution Output:*
```text
  GitWork
* master
```

#### 18. Delete merged branch `GitWork`
```bash
git branch -d GitWork
```
*Actual Execution Output:*
```text

```

#### 19. Observe log graph after merge conflict resolution
```bash
git log --oneline --graph --decorate
```
*Actual Execution Output:*
```text

*   dc1260c Merge branch GitWork and resolve merge conflict in hello.xml
```

---

## Key Takeaways
1. Merge conflicts occur when Git cannot automatically reconcile conflicting edits on the same file lines.
2. Conflict markers `<<<<<<<`, `=======`, and `>>>>>>>` clearly highlight the contrasting code blocks.
3. Once conflicts are resolved, files must be staged with `git add` and committed with `git commit` to finalize the merge.
4. Temporary backup files created by merge tools should be ignored using `.gitignore` (`*.orig`, `*.bak`).
